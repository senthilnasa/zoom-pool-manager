> **Milestone:** M6 — Host Control & Access Security  
> **Status:** Verified  
> **Environment:** Docker (PHP 8.3 FPM / CLI + MariaDB 10.6 + Nginx) & Shared Hosting Target

## 1. Automated Test Suite Results

Execute inside the PHP 8.3 environment:
```bash
./vendor/bin/pest
./vendor/bin/pint --test
./vendor/bin/phpstan analyse --memory-limit=512M
```

### Verification Checklist:
- [x] Feature: `Tests\Feature\HostControlTest`
  - [x] **JIT Start Meeting Window**: Meeting organizer can start a meeting during the 15-minute window prior to start time (`starts_at - 15min`) through meeting conclusion (`ends_at`). Issues a secure 302 redirect directly to Zoom without ever persisting, emailing, or logging the `start_url`.
  - [x] **Early / Late Access Prevention**: Attempts to start the meeting too early (e.g. 2 hours before) or after the meeting ends are blocked with a clear user alert.
  - [x] **Unauthorized Access Rejection**: Non-owners and users lacking IT administrator privileges are forbidden from accessing host control endpoints.
  - [x] **Emergency IT Override**: IT Administrators and Super Admins can emergency-start meetings even outside the standard owner window, provided a mandatory explanation reason is supplied. Creates an immutable record in `overrides` and logs `meeting.it_emergency_start` in `audit_logs`.
  - [x] **Host Key Reveal**: Meeting organizers can securely reveal the 6-digit numeric host PIN during the active window to claim host privileges inside the Zoom desktop/mobile client. Every reveal event is audited (`host_key.revealed`).
  - [x] **Emergency Host Key Access**: IT Administrators can reveal host keys with a mandatory audit reason recorded in `overrides`.
  - [x] **Host Key Rotation**: Automated/manual host key rotation generates a new random 6-digit PIN, updates the encrypted `host_key` on `zoom_users`, and logs `host_key.rotated`.

## 2. Manual Verification Walkthrough

### Step 1: Start Meeting as Organizer
1. Log in as a meeting owner with a meeting starting within 15 minutes.
2. Navigate to `http://localhost:8000/meetings/{publicId}`.
3. Observe the green **Start Meeting (Host)** button in the header.
4. Click **Start Meeting (Host)**.
5. Verify browser is redirected away (HTTP 302) to the Zoom launch URL (`https://zoom.us/s/...`).
6. Verify no `start_url` string is stored in the database or written to log files.

### Step 2: Test Start Restriction on Future Meetings
1. View a meeting scheduled 2 days in the future.
2. Verify the **Start Meeting (Host)** button is not present for the owner.
3. Manually attempting to access `/meetings/{publicId}/start` redirects back with the message: *"The meeting start button is only available from 15 minutes prior to scheduled start time until the meeting concludes."*

### Step 3: Reveal Host Key in Modal
1. On an active meeting page, click **Host Key**.
2. In the modal, click **Reveal Host Key**.
3. Observe the 6-digit PIN display and the security notice explaining that the key is rotated automatically upon meeting conclusion.
4. Verify an audit entry is created in `audit_logs` with event `host_key.revealed`.

### Step 4: IT Administrator Emergency Override Flow
1. Log in as an IT Administrator (`it_admin` or `super_admin`).
2. Navigate to a meeting owned by another user.
3. Click **IT Emergency Start**.
4. Observe the modal prompting for a mandatory override reason.
5. Enter reason (e.g., *"Instructor equipment failure, technician launching room to test audio"*) and submit.
6. Verify redirection to the host URL and that an `overrides` entry and audit record have been persisted.
