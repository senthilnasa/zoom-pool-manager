## 1. Automated Test Suite Results

Execute inside the PHP 8.3 environment:
```bash
./vendor/bin/pest

```

### Verification Checklist:
- [x] Feature: `Tests\Feature\EffectivePolicyResolverTest`
  - Resolves organization-level baseline defaults for buffers, notice, advance days, and durations.
  - Security Profile enforcement: security profile overrides lower layers (e.g. locks AI Companion to `DISABLED`).
  - Department Booking Policy restriction: departments can enforce stricter notice (e.g. 24h), longer buffers, and reduced advance days.
  - Privileged roles bypass notice limits (`minNoticeHours = 0`).
  - User request constraints: requests cannot reduce buffer below organization minimum.
- [x] Feature: `Tests\Feature\ConflictDetectionTest`
  - Validates minimum notice window, triggering `notice_violation` if meeting is too soon.
  - Validates maximum advance booking window, triggering `advance_booking_violation`.
  - Validates blackout periods (both organization-wide and department-specific), triggering `blackout_conflict`.
  - Validates participant capacity against active pooled resources, triggering `capacity_mismatch`.
- [x] Feature: `Tests\Feature\AllocationEngineTest`
  - Concurrency safety: atomic database transaction holding resources with `SELECT ... FOR UPDATE` ordered strictly by ID to prevent deadlocks.
  - Buffer occupancy: `occupied_until` strictly stores `ends_at + buffer_minutes` in `resource_reservations`.
  - Buffer edge case: meeting starting exactly when previous buffer ends (`starts_at == previous.occupied_until`) is permitted.
  - Buffer overlap: meeting starting 1 minute before buffer ends is blocked.
  - External meeting protection: reservations from external Zoom imports block allocation.
  - Strategy `least_hours_today`: assigns resource with lowest total occupied minutes today.
  - Strategy `priority`: assigns resource with highest priority (lowest numerical value).
  - Expired hold cleanup: `releaseExpiredHolds()` automatically releases reservations held longer than 10 minutes.

## 2. Manual Verification Walkthrough

### Step 1: Effective Policy Resolution via Tinker
1. Launch Tinker:
   ```bash
   php artisan tinker
   ```
2. Test resolving effective policy with department restrictions:
   ```php
   $resolver = app(\App\Domain\Scheduling\Services\EffectivePolicyResolver::class);
   $policy = $resolver->resolve();
   echo "Buffer: {$policy->bufferMinutes}m, Min Notice: {$policy->minNoticeHours}h\n";
   ```

### Step 2: Atomic Resource Holding & Buffer Inspection
1. Query reservations table after a test hold:
   ```sql
   SELECT id, resource_id, occupied_from, occupied_until, status, hold_expires_at FROM resource_reservations ORDER BY id DESC LIMIT 5;
   ```
2. Verify `occupied_until` is exactly `ends_at + bufferMinutes`.

### Step 3: Concurrency & Lock Ordering Verification
1. Inspect `app/Domain/Scheduling/Services/AllocationEngine.php`.
2. Confirm the lock query utilizes:
   ```php
   ZoomResource::whereIn('id', $candidateIds)->orderBy('id', 'asc')->lockForUpdate()->get();
   ```
3. Verify that deadlocks are mathematically eliminated through consistent ascendant key acquisition.
