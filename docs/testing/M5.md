## 1. Automated Test Suite Results

Execute inside the PHP 8.3 environment:
```bash
./vendor/bin/pest
./vendor/bin/pint --test
./vendor/bin/phpstan analyse --memory-limit=512M
```

### Verification Checklist:
- [x] Feature: `Tests\Feature\MeetingStateMachineTest`
  - Lifecycle state machine strictly enforces permitted transitions:
    `draft -> pending_approval -> approved -> allocating -> scheduled -> started -> ended -> completed`.
  - Illegal transitions throw a `RuntimeException` (e.g. `completed -> started`).
  - Permitted cancellations (e.g. from `scheduled` to `cancelled`) record cancellation reasons.
  - State changes automatically append immutable audit entries to `meeting_status_history`.
- [x] Feature: `Tests\Feature\AgendaMarkerServiceTest`
  - Injects `[ZPM:{public_id}]` into meeting agenda/description for Zoom webhook idempotency and bidirectional tracking.
  - Deduplication prevents duplicate marker injection if marker is already present.
  - Regex extractor reliably extracts public identifiers (`01HX...`).
  - Stripping helper cleanly removes marker tags for end-user display.
- [x] Feature: `Tests\Feature\MeetingBookingTest`
  - Live AJAX preview endpoint (`POST /meetings/preview-conflicts`) returns conflict diagnosis and available resource counts before submission.
  - Form submission creates `meetings` row with status `allocating` and holds resource in `resource_reservations` covering `[starts_at, ends_at + buffer]`.
  - Parses comma-separated invitees and seeds `meeting_invitees`.
  - Cancellation endpoint (`POST /meetings/{id}/cancel`) cancels meeting and automatically transitions held/confirmed reservations to `released`.
  - Web UI routes render: `meetings.index`, `meetings.create`, `meetings.show`, `calendar`.

## 2. Manual Verification Walkthrough

### Step 1: Browse Meetings Dashboard
1. Navigate to `http://localhost:8000/meetings` as an authenticated user.
2. Verify list displays meeting title, type, scheduled date/time, assigned resource, and status badge.

### Step 2: Book a Pooled Meeting
1. Click **Book New Meeting** (`/meetings/create`).
2. Input start time, end time, attendee count, template, and security profile.
3. Observe the live preview card checking for conflicts in real time.
4. Submit the booking request.
5. Verify redirect to `/meetings/{publicId}` showing meeting details, assigned resource, and lifecycle audit trail.

### Step 3: Check Resource Timeline Calendar
1. Navigate to `http://localhost:8000/calendar`.
2. Inspect the resource occupancy grid showing active resources, participant capacity, and today's reservations with buffer windows.

### Step 4: Meeting Cancellation & Resource Release
1. On `/meetings/{publicId}`, click **Cancel Meeting**.
2. Enter cancellation reason in the modal and confirm.
3. Verify meeting status updates to `Cancelled` and the resource reservation in `resource_reservations` is marked `released`.
