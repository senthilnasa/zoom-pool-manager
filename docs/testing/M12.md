## 1. Deliverables Implemented

### 1.1 Database Architecture
- **`api_keys`**: Stores scoped API keys with hashed secret tokens (`public_id`, `user_id`, `name`, `key_prefix`, `key_hash`, `scopes`, `rate_limit_per_minute`, `last_used_at`, `expires_at`, `revoked_at`). Tokens use `zpm_live_` prefix and SHA-256 hash storage.
- **`idempotency_records`**: Caches idempotent responses for POST/PUT requests using client-provided `Idempotency-Key` headers (`key`, `user_id`, `api_key_id`, `route`, `request_hash`, `response_status`, `response_headers`, `response_body`).
- **`webhook_subscriptions`**: Tracks outbound webhook endpoints (`public_id`, `name`, `url`, `secret`, `events`, `is_active`, `failure_count`, `last_delivered_at`, `created_by_user_id`).
- **`webhook_deliveries`**: Log of dispatched webhook payloads and HTTP response acknowledgments (`public_id`, `subscription_id`, `event_type`, `payload`, `signature`, `response_status`, `response_body`, `attempt`, `status`, `delivered_at`).

### 1.2 Authentication & Middleware (`App\Http\Middleware`)
- **`AuthenticateApiKey`**:
  - Validates `Authorization: Bearer zpm_live_...` headers against SHA-256 key hash.
  - Rejects missing, invalid, expired, or revoked API keys with HTTP 401.
  - Enforces per-key rate limiting with HTTP 429 (`Retry-After`, `X-RateLimit-Limit`).
  - Sets authenticated user and binds `api_key` attribute to incoming request.
- **`RequireApiScope`**:
  - Validates granted permissions per endpoint (`meetings:read`, `meetings:write`, `availability:read`, `pools:read`, `recordings:read`). Returns HTTP 403 on missing scopes.
- **`HandleIdempotency`**:
  - Intercepts `Idempotency-Key` headers on mutating requests.
  - Matches previous payload hash and returns cached response with `X-Cache: HIT-IDEMPOTENT`.
  - Rejects conflicting payload reuse on same key with HTTP 422.

### 1.3 REST API Endpoints (`/api/v1`)
- **`GET /api/v1/availability`**: Inspects real-time pool availability and conflict analysis for proposed time windows without making reservations.
- **`GET /api/v1/meetings`**: Lists meetings with status, time range filters, and department/ownership scoping.
- **`POST /api/v1/meetings`**: Creates and books meetings atomically via `MeetingService`, firing `meeting.created` outbound webhook event.
- **`GET /api/v1/meetings/{public_id}`**: Retrieves meeting details, resource allocation, and join links.
- **`POST /api/v1/meetings/{public_id}/cancel`**: Cancels meeting and releases resource reservation, firing `meeting.cancelled` outbound webhook event.
- **`GET /api/v1/pools`**: Lists active resource pools, strategies, and member resources.
- **`GET /api/v1/recordings`**: Lists indexed cloud recordings for authenticated user.
- **`GET /api/v1/recordings/{public_id}`**: Retrieves recording details and playback access URL with audit logging.

### 1.4 Interactive OpenAPI Documentation (`/docs/api`)
- Configured **Dedoc Scramble** (`config/scramble.php`) for automatic OpenAPI 3.0 specification generation.
- Interactive documentation rendered at `/docs/api` with schema descriptions and JSON specification at `/docs/api.json`.
- Access controlled by `viewApiDocs` Gate.

### 1.5 Outbound Webhooks Dispatcher
- **`OutboundWebhookService`**: Filters matching active subscriptions and queues delivery records.
- **`DispatchOutgoingWebhookJob`**:
  - Sends signed HTTP POST requests with headers: `X-ZPM-Delivery`, `X-ZPM-Event`, `X-ZPM-Timestamp`, `X-ZPM-Signature: sha256=<hmac>`.
  - Exponential backoff retries (10s, 60s, 300s) on connection failures or non-2xx responses.
- **Admin Management Portal (`/admin/outbound-webhooks`)**:
  - Register endpoints, configure event subscriptions, trigger live test pings, toggle active state, and manually retry failed deliveries.
