## 1. Deliverables Implemented

### 1.1 Database Architecture
- **`notifications`**: Polymorphic in-app notification center table storing user notifications, type classification (`booking`, `approval`, `security`, `system`), data payload, read/viewed timestamps, and urgency level.
- **`email_templates`**: Whitelisted Jinja/Blade-like placeholder templates for 8 core transactional events (`meeting_confirmed`, `meeting_cancelled`, `meeting_updated`, `host_key_revealed`, `approval_required`, `approval_decided`, `meeting_reminder`, `security_alert`), with subject, HTML body, plain text body, enabled flags, and system lock protections.
- **`email_deliveries`**: Auditable mail delivery log with strict deduplication keys (`dedupe_key = event_id + recipient + template_key`), delivery state tracking (`pending`, `sent`, `failed`), provider metadata, error logs, and retry attempt counters.
- **`notification_preferences`**: Granular user notification settings per channel (`email`, `in_app`) and event type. Critical security alerts and administrative audit events are strictly non-disableable.

### 1.2 Mail Providers & Manager (`App\Domain\Mail`)
- **`MailProviderInterface`**: Unified contract with `send()`, `getName()`, and `verifyConfiguration()` methods.
- **`SmtpMailProvider`**: Standard SMTP mail driver configured via encrypted settings/environment.
- **`GmailApiMailProvider`**: Google Workspace API mail delivery using OAuth2 service credentials.
- **`MicrosoftGraphMailProvider`**: Microsoft 365 / Entra ID mail delivery using MS Graph API.
- **`LogMailProvider`**: Development, staging, and demo driver logging message headers and bodies without transmitting external mail.
- **`MailProviderManager`**: Driver resolver with fallback safety, configuration health verification, and dynamic provider switching.

### 1.3 Communication & Calendar Services (`App\Domain\Communication\Services`)
- **`IcsCalendarService`**: Generates RFC 5545 compliant `.ics` iCalendar invites using `spatie/icalendar-generator`. Supports:
  - Stable UIDs: `zpm-{public_id}@{hostDomain}` for reliable updates across calendar clients.
  - Sequence tracking for updates (`SEQUENCE:n`).
  - Cancellation methods (`METHOD:CANCEL`, `STATUS:CANCELLED`).
  - Timezone specifications, join URL embedding, and sanitized descriptions.
- **`TemplateRenderer`**: Whitelist-based template interpolation substituting safe variables (e.g., `{{ meeting_title }}`, `{{ starts_at }}`, `{{ join_url }}`) while strictly protecting sensitive data (`start_url` and raw host keys are NEVER exposed in templates).
- **`MailDeliveryService`**: Queued email delivery with cryptographic deduplication keys preventing double-sends, retry backoff, and delivery audit logging.
- **`NotificationCenterService`**: In-app notifications with unread badge counts, read state toggles, and mandatory delivery for security events.
- **`MeetingNotificationService`**: Event-driven orchestrator coordinating user preferences, template selection, and calendar attachments across the meeting lifecycle.

### 1.4 Web Interface & Console Commands
- **In-App Notification Center**: `/notifications` for listing alerts, marking individual items or all items as read.
- **Mail Settings & Diagnostic Testing**: `/mail/settings` for configuring providers (SMTP, Gmail API, MS Graph, Log) and sending test diagnostic emails.
- **Email Template Management**: `/mail/templates` and `/mail/templates/{id}/edit` for customizing message subjects and templates with live variable suggestions.
- **Email Delivery Logs**: `/mail/deliveries` for viewing delivery history, statuses, and retry attempts.
- **Direct ICS Download**: `/meetings/{public_id}/ics` for calendar invite export.
- **Scheduled Reminder Command**: `php artisan zpm:notifications:send-reminders` running every 5 minutes to trigger 15-minute and 24-hour meeting notifications.
